################################################################################
COMMIT: Fix Unselected Provider Booking Count & Premature Database Creation
DATE: 2026-11-21
AUTHOR: Quick-Fix Development
MODULES AFFECTED: QUICK-FIX-BACKEND, QUICK-FIX-FRONT-END
################################################################################

1. PROBLEM IN PREVIOUS VERSION:
-------------------------------
- When a customer proceeded through the booking process (Service -> Address ->
  Provider Selection), the frontend page `ProviderSelectionPage.jsx` immediately
  fired a POST request to `/api/bookings` on component mount.
- This was done because the only backend endpoint available to find nearby
  providers (`GET /api/bookings/{bookingUniqueId}/providers`) required an existing
  `bookingUniqueId`.
- As a direct result, an incomplete booking row was inserted into the MySQL
  database with status `PENDING` and NO provider assigned (`provider_id = null`).
- If the customer left the page, closed their browser, clicked Back, or had not
  yet picked a provider, that orphan booking remained permanently in the database.
- Furthermore, the Customer Dashboard (`CustomerDashboard.jsx`), Customer Profile
  (`CustomerProfilePage.jsx`), and My Bookings page (`MyBookingsPage.jsx`) counted
  any booking with status `PENDING` toward active booking statistics.
- This caused the dashboard to display "Active Bookings: 1" and show an
  "Upcoming Booking: Home Service" card with "Quick-Fix Provider" before the user
  even finished selecting a provider.


2. HOW IT IS SOLVED NOW:
------------------------
- Added a dedicated direct provider discovery endpoint in the backend:
  `GET /api/bookings/providers?serviceUniqueId=...&latitude=...&longitude=...`
  This finds and returns eligible nearby providers using the service ID and location
  coordinates WITHOUT saving any booking to the database.
- Removed premature `bookingApi.createBooking(...)` from `ProviderSelectionPage.jsx`
  on mount. The provider list is fetched directly through the new endpoint.
- The booking in the database is ONLY created when the customer actually chooses
  a provider and clicks "Confirm Booking" on the review screen.
- Added `DRAFT` status to the `BookingStatus` enum.
- Added `providerUniqueId` to `BookingRequestModel` so that `createBooking` can
  assign the provider, calculate distance, and set status to `WAITING_FOR_PROVIDER`
  in a single atomic request.
- Added an "Exit & Discard Draft" button so users can cancel and exit cleanly.
- Updated all frontend statistics filters and backend queries to exclude `DRAFT`
  bookings and unassigned bookings (`hasProvider == false`).

FILE 5: QUICK-FIX-FRONT-END/src/api/bookingApi.js
--------------------------------------------------------------------------------
- PREVIOUS PROBLEM:
  Lacked a client method to find providers by coordinates/address, and did not
  pass `providerUniqueId` in `createBooking`.

- WHAT CHANGED:
  - Added `providerUniqueId` to `createBooking` payload.
  - Added `findNearbyProviders({ serviceUniqueId, latitude, longitude, addressUniqueId })`.
  - Added `deleteBooking(bookingUniqueId)`.

- HOW IT CHANGED:
  [AFTER]
    createBooking: async (customerUniqueId, bookingRequest) => {
      const payload = {
        ...
        providerUniqueId: bookingRequest.providerUniqueId || null
      };
      const res = await axiosInstance.post('/bookings', payload, {
        params: { customerUniqueId }
      });
      return normalizeBooking(res.data);
    },

    findNearbyProviders: async ({ serviceUniqueId, latitude, longitude, addressUniqueId }) => {
      const params = { serviceUniqueId };
      if (latitude != null && longitude != null) {
        params.latitude = latitude;
        params.longitude = longitude;
      }
      if (addressUniqueId) {
        params.addressUniqueId = addressUniqueId;
      }
      const res = await axiosInstance.get('/bookings/providers', { params });
      return res.data;
    },

    deleteBooking: async (bookingUniqueId) => {
      const res = await axiosInstance.delete(`/bookings/${bookingUniqueId}`);
      return res.data;
    }

- HOW IT SOLVED THE PROBLEM:
  Provided frontend pages with clean API functions to discover providers and
  submit confirmed bookings in one step.
